# Zanka no Tachi 1.0.0 — stable release notes and handoff

**Prepared 2026-09-24; publication pending.** The first stable version promotes
the maintainer-approved RC.1 with metadata and documentation changes only. No
tag, GitHub Release or public APK upload is authorized by this preparation.

## Product

One adaptive Android app for phones/tablets and remote-first TV use:

- Canonical multi-source manga/anime Library with Smart Resume and completion
  independent of provider identifiers.
- Manga reading with bounded chapter continuity/navigation, page-aware exact
  resume, paged RTL/LTR or vertical modes, zoom/pan and read/unread controls.
- Anime playback with Previous/Next, episode picker, completion actions,
  watched/unwatched, exact source-specific resume and TV remote controls.
- Engine-neutral Video Display Mode with intrinsic-ratio Auto / Original,
  explicit fit/crop/stretch, ratio presets and custom positive ratios.
- Lawful local media import/repair, data-only portable backup and supported
  public provider resources, without access-control bypass.

No functionality changes from RC.1. This preparation does not update dependencies,
toolchains, source behavior, database schemas or backup formats.

## Production and data guarantees retained

Production excludes demo/sample assets, sample installers, Developer UI and the
experimental engine selector. `video_player` remains its only selectable engine,
even with a stale device-local experimental preference. Better Player's native
plugin/transitive dependencies remain packaged; no native-removal claim is made.

Database schema **6** and backup format **3** are unchanged. Supported formats 1
and 2 remain readable. Restore is additive rather than replacing the library;
newer progress is retained and exact page/timestamp resume is binding-specific.
Engine and display preferences remain device-local on the receiving device.
Backups omit media bytes and local paths: retain originals separately and repair
missing local assets after restoring to another installation.

The WorkManager/Room `WorkDatabase_Impl` reflected-constructor fix at `98d3b2e`
is retained with R8 shrinking enabled. `tool/verify_release_startup.sh` checks
the actual APK DEX for the public constructor before the artifact is handed off.
This guard is necessary but is not a substitute for observing a cold launch.

## Reproducible packaging

From the clean stable preparation commit, select the existing full JDK 21 via
`ZANKA_JAVA_HOME`/`JAVA_HOME` and run `tool/release_android.sh`. It repeats format,
analyzer, development and production-profile tests, then signs production and
checks package, version, permanent signer and the packaged constructor. It
does not commit, push, tag or upload anything. Verify versionCode 7 and the
non-debuggable flag on the actual APK, as well as production asset exclusion.

- Source: `build/app/outputs/flutter-apk/app-production-release.apk`.
- Handoff: `artifacts/zanka-no-tachi-v1.0.0.apk` and its `.sha256`.
- Retain the matching R8 mapping privately; never commit APKs or signing data.
- Keep the RC.1 artifact/checksum intact. Do not reuse its hash for stable 1.0.0.

## Stable artifact handoff checklist

1. Verify stable APK SHA-256, package, version/build and permanent signer against
   the handoff. Export a backup outside app-private storage; keep original media.
2. Install the same artifact **in place** on each intended physical device:
   `adb -s SAMSUNG_SERIAL install -r zanka-no-tachi-v1.0.0.apk` and
   `adb -s FIRE_SERIAL install -r zanka-no-tachi-v1.0.0.apk`.
   Packaging does not modify either device; installation is a maintainer check.
3. Cold-open Home, check About `1.0.0`/build `7`, retained Library/imports/settings,
   completion and exact manga/anime resume. Close and reopen; check fresh logs.
4. Samsung: reader/chapter continuity and player seek/Next/Previous/fullscreen.
   Fire: launcher, D-pad navigation, Back, media controls and HOME/return.
   Production must not expose demo or Developer controls.
5. Keep fresh onboarding and restore checks on disposable installations only.
   Do not reset personal devices. Retain their evidence separately; preserve
   repairable asset behavior and receiving-device preferences on restore.
6. Record exact APK hash, model/OS and observed results. Only after stable
   artifact approval may the maintainer explicitly authorize a tag/GitHub Release
   and public distribution. None is created by this handoff.

Provider availability and delivery can change. Unsupported media stays
unavailable; advanced track selection, cloud sync, background playback, TV
recommendations and Vega OS are not promised. Zanka is independent/unofficial
and grants no rights to third-party content.
