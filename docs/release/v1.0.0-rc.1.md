# Zanka no Tachi 1.0.0 RC.1 — preparation and handoff

**Candidate only; not published and not stable 1.0.** This preparation changes
release metadata/documentation, not the validated product implementation.

## Identity and artifact

- Version: `1.0.0-rc.1+6` (`versionName 1.0.0-rc.1`, `versionCode 6`).
- Published release metadata and Git version history were checked before
  preparation: the highest prior production build is beta.4, code 5. The
  corrected pre-RC APK also has code 5; RC.1 is strictly newer.
- Production: `dev.zanka.notachi`; development: `dev.zanka.notachi.debug`.
- Permanent external signer: alias `zanka-release`, RSA 4096-bit, certificate
  SHA-256 `3F:4A:86:F7:F4:DD:A3:98:E0:4D:D0:59:DD:33:D7:FC:27:4C:AC:B3:62:17:A4:68:B6:D8:D7:C7:07:4C:13:41`.
- Source APK: `build/app/outputs/flutter-apk/app-production-release.apk`.
- Versioned handoff: `artifacts/zanka-no-tachi-v1.0.0-rc.1.apk` and
  `artifacts/zanka-no-tachi-v1.0.0-rc.1.apk.sha256`.

Run `tool/release_android.sh` from the clean preparation commit with a full
JDK 21 selected through `ZANKA_JAVA_HOME`/`JAVA_HOME`. The workflow checks format,
analyzer, full development tests and production-profile tests, builds/signs
production, verifies the packaged WorkDatabase constructor, package, version
and permanent signer, and emits the versioned APK/checksum. It does not tag,
upload or publish. The final handoff must record the actual commit, byte size
and checksum after the build, rather than reusing beta.4's artifact values.

## Unchanged production and data contracts

- Production excludes demo assets, sample installers, Developer UI and the
  experimental engine selector. `video_player` remains its only selectable
  playback engine, regardless of an old device-local experimental preference.
- Better Player's native plugin/transitive dependencies remain packaged. Do
  not claim native removal merely because its production selector is absent.
- Database schema **6**, additive migrations, and backup format **3** remain
  unchanged. Older supported formats (1 and 2) remain readable.
- Restore merges rather than replacing the library; newer progress is retained.
  Exact resume remains source/binding-specific. Engine selection and Video
  Display Mode remain device-local and are preserved on the receiving device.
- Data-only backups omit media bytes and local paths. Local assets restored on
  another installation are missing/repairable; retain originals separately.
- The startup fix at `98d3b2e` keeps only Room's reflectively called
  `WorkDatabase_Impl` constructor. R8 shrinking and WorkManager remain enabled;
  `tool/verify_release_startup.sh` checks the actual APK, not just source rules.

## Candidate installation checklist

1. Check the handed-off RC checksum, package, version/build and permanent signer.
   Export a data-only backup from each existing installation to a safe location
   outside the app first; preserve original media separately.
2. Samsung: `adb -s SAMSUNG_SERIAL install -r zanka-no-tachi-v1.0.0-rc.1.apk`.
   Fire Stick: connect normally, then
   `adb -s FIRE_SERIAL install -r zanka-no-tachi-v1.0.0-rc.1.apk`.
   These are in-place updates of production-signed beta.2+; **do not uninstall
   or clear data**. If identity/signature verification fails, stop instead of
   removing the existing app. The development/debug APK is not a substitute.
3. On both devices, cold-open Home and check About reports RC.1. Verify saved
   Library, local imports, preferences, completion and exact page/timestamp
   resumes survived. Close/reopen and recheck. Confirm Developer/demo controls
   are absent; use lawful existing/imported content for playback/reading.
4. Samsung: reader page/chapter continuity and video seek/Next/Previous with
   fullscreen continuity. Fire: launcher, D-pad focus/activation, Back, media
   keys and HOME/return with retained exact resume. Check fresh startup logs.
5. Test backup preview/restore **only on a disposable installation**. Confirm
   existing records/newer progress are not replaced, local assets are
   repairable, and device-local display/engine settings are not imported.
6. Test fresh production onboarding separately on a disposable installation,
   including empty Home/Library, Settings and cold reopen. Never reset either
   maintainer device to obtain a fresh-install result.
7. Record device/model, Android/Fire OS, APK SHA-256 and per-check result. Keep
   unavailable/unperformed checks pending; emulator success is not physical
   certification. Any public tag/release requires separate authorization.

Known limitations remain unchanged: provider availability can vary, unsupported
delivery stays unavailable, advanced track selection is not promised, and cloud
sync/background playback/Vega OS are out of scope. This RC grants no rights to
third-party content and implements no access-control bypass.
